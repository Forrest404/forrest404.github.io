Games for unidex

27 Oct

unidex runs games now, as well as apps. Still Lua, still one button. That keeps them small. E-ink is slow to redraw, so they have to work around that.

A game is marked "type": "game" in its JSON and needs API 4. You write four functions: start (sets it up), step (moves things on one tick), draw (puts it on the screen) and score (what shows at the end).

B can be tapped or held, and the two count as different inputs. There's a seed too, so a game can be random and still repeatable. Frames run on the fast e-ink mode. GAMES.md in unidex-apps has all of it, with a checklist.

The first game is Hop. Blocks come in from the right and you tap B to hop over them. It's in unidex-apps too.

Then I wrote a course that builds Hop from scratch: "Make your own unidex game", 8 lessons, at learn.unidex.shop. The lesson runner can install and open a game now. There's also a test that plays every game lesson. The finished answer has to pass and the starter code has to fail, which catches lessons that give the answer away or can't be finished.

A few small API things went in along the way. unidex.wifi.scan() (API 2) lists nearby networks: name, signal and security, never an address. unidex.frame(ms) (API 3) shows an animation frame in the middle of a function. unidex.chime() (API 5) is for timers and alarms.
